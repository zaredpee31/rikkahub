# 阿辞的消息

## 范围
- 独立消息聊天页、设置页和通知入口；只有绑定会话接收主动消息。
- 回复复用 ChatService 的助手、模型、工具和共享记忆。工具确认或错误详情可打开原会话。
- 手机是人设、记忆和近期会话的权威；通过鉴权 HTTPS 上传快照。
- 服务器快照使用 Fernet 加密；收件箱保存在本机受权限限制的 SQLite 中。服务器不回写手机记忆。
- 后台生成支持 Claude Messages、OpenAI Chat Completions 和 Responses 兼容接口；后台不调用 MCP 工具。

## 时间规则（Asia/Shanghai）
- 周一至周五 08:00 时段生成一次早安，获取西安当天天气；天气失败时明确不编造。周六日不生成早安。
- 心跳工作日 09:00–23:00、周末 11:00–23:00。每次抽取下一次机会，取消三小时间隔和每日三条额度。
- 部分间隔为 8–40 分钟，多数为半小时加随机等待，部分间隔可跨天；模型可返回 [SKIP] 保持安静。
- 最近十五分钟有人发言、正在生成或快照超过48小时则暂停。
- 未回复时偶尔追发一句；最多两条未送达，超过一天的旧已送达消息不永久阻塞新机会。ack仅表示送达，不代表已读。
- 防并发锁、稳定消息UUID和早安日期槽防重复；生成期间上下文变化则丢弃旧生成。

## 运行
使用独立虚拟环境 /home/ubuntu/companion-runtime 和数据目录 /home/ubuntu/companion-data。
安装 companion-messages.service 后用 systemctl 管理；仅监听127.0.0.1:8850。
Caddy.fragment 只是待批准的新增转发，不要覆盖现有Caddyfile。
aci-mcp、网页、QQ相关服务和旧早安不属于本服务，不应删除或重启。

## 验证
python3 -m unittest discover -s companion-server -v
server.py --tick：检查一次；--tick --force：手工触发一次机会，但仍尊重关闭、静默时间、活跃用户和待回复限制。
模型失败、截断或流中断不投递半截消息。日志不包含API密钥、人设和消息正文。

## 安卓
通过GitHub Actions build-debug.yml构建，不在服务器编译安卓。
首次进入侧边栏“阿辞的消息”，新建专属会话，再启用同步和通知。
前台接收器每分钟检查，未变化快照最多每15分钟刷新；WorkManager用作系统限制下的备用。
强制停止、省电限制、无网络、通知权限关闭都可能延迟接收；不能保证手机在08:00整点弹出。
正式端到端验证需安装APK、开启同步、连接模型，再用真机检查回复和通知。
